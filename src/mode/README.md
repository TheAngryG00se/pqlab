# Режимы участника 3

ECB, CBC и CTR реализуют существующий `pq::CipherMode` поверх переданного
`std::unique_ptr<BlockCipher>` и не включают заголовков конкретных шифров.
В `register.hpp` находится `pq::mode::register_algorithms(Registry&)`.
Тесты используют локальный реестр; глобальный реестр участника 4 не меняется.

- ECB: без IV и дополнения, длина кратна блоку; пустой ввод разрешён.
- CBC: IV длиной в блок, всегда PKCS#7, включая дополнительный блок при
  кратной длине. Весь последний блок проверяется до публичного решения о
  допустимости дополнения. При отказе возвращается `nullopt`, открытый текст
  не выдаётся. Длина блока должна быть от 1 до 255 байт.
- CTR: IV — начальное значение счётчика, увеличивается весь блок как
  big-endian число. Любая длина сообщения. Переполнение через максимальное
  значение отвергается до обработки данных; самый последний счётчик можно
  использовать один раз. Все счётчики для одного ключа должны быть различны
  и между отдельными вызовами; это обязанность вызывающего кода.

Временный открытый текст, дополнение и гамма находятся в `SecureBytes`.
Выделения памяти выполняются до блочных циклов. Режимы не добавляют
проверку подлинности и предназначены для замеров/анализа; KEM-DEM использует AEAD.
CBC требует непредсказуемого IV. Эти требования следуют из SP 800-38A,
§6.1, §6.2, §6.5, приложений B/C и RFC 5652 §6.3.

Официальные примеры для AES всех размеров находятся в `tests/kat/modes/`.
Для CBC сравниваются все четыре официальных блока и отдельно проверяются
дополнение, отказ и пограничные длины; дополнительный блок не объявляется
официальным KAT. Свойства проверяются также на «Кузнечике».

GCM реализует `pq::Aead` для любого 128-битного блочного шифра. Поддерживается
профиль PQL1: nonce 12 байт, тег 16 байт, результат `ciphertext || tag`.
Длины ограничены SP 800-38D: сообщение не больше 2^36−32 байт,
AAD не больше floor((2^64−1)/8) байт. Nonce при одном ключе не должен
повторяться; этот объект не хранит историю nonce между вызовами.

GHASH реализован отдельно без таблиц и ветвлений по секретам, по алгоритмам
1/2 SP 800-38D. `open` сначала проверяет тег через `ct_equal` и только потом
расшифровывает; подмена и слишком короткий шифротекст дают `nullopt`.
Неверные длины ключа/nonce и превышение лимитов — `pq::Error`.

Тесты выполняют все 2250 CAVP случаев поддерживаемого профиля для
AES-128/192/256 (в том числе FAIL), официальные промежуточные GHASH-примеры,
проверки подмен и локальную интеграцию всех доступных KEM × четырёх шифров.
«Кузнечик»-GCM — композиция учебного стенда; векторы AES-GCM не являются
официальной валидацией этой композиции. Её проверяют свойства и интеграция.
