# src/hash: Keccak, SHA-3, SHAKE, HMAC, HKDF, PBKDF2

Owner: participant 1. Namespace `pq::hash`.

| File | What | Standard |
|---|---|---|
| `keccak.{hpp,cpp}` | KECCAK-f[1600], byte-oriented incremental sponge | FIPS 202, Sections 3, 4, 5 |
| `sha3.{hpp,cpp}` | SHA3-256, SHA3-512 | FIPS 202, Section 6.1 |
| `shake.{hpp,cpp}` | SHAKE128, SHAKE256 with streaming squeeze | FIPS 202, Section 6.2 |
| `hmac.{hpp,cpp}` | HMAC-SHA3-256 (block size 136 bytes) | RFC 2104, FIPS 198-1 |
| `hkdf.{hpp,cpp}` | HKDF-SHA3-256 extract / expand | RFC 5869 |
| `pbkdf2.{hpp,cpp}` | PBKDF2-HMAC-SHA3-256 | RFC 8018, Section 5.2 |

Round constants and rho offsets are computed at compile time from FIPS 202, Algorithms 5
and 2, instead of being copied as tables.

Verification:
- SHA-3 and SHAKE: NIST CAVP SHA3VS byte vectors, including Monte Carlo (`tests/kat/sha3`).
- HMAC, HKDF, PBKDF2: values generated by OpenSSL (`tests/kat/kdf`).

Known limitations:
- Byte-oriented only: messages and outputs are whole bytes (all users in the project need
  only that).
- The plain reference permutation, no lane complementing or unrolling.
