# Анализ участника 3: теория и API

Блочный шифр превращает блок сообщения в блок шифротекста под управлением ключа.
AES и «Кузнечик» работают с блоком 128 бит. Раунд — один шаг перемешивания:
нелинейная замена байтов скрывает простые зависимости, линейное преобразование
распределяет изменение по блоку, добавление ключа связывает результат с секретом.
Режим работы позволяет обрабатывать сообщения длиннее одного блока.

Лавинный эффект означает, что изменение одного входного бита должно менять
примерно половину выходных. Для 128 бит ориентиры: среднее расстояние Хэмминга
64, дисперсия 32. Это свойства модели случайного отображения, а не гарантия
криптографической стойкости. Движок проверяет сообщения и ключи отдельно.

SAC — вероятность изменения выходного бита j при изменении входного i;
идеальное значение 1/2. BIC проверяет корреляцию двух индикаторов изменения
выходных битов при одном входном направлении; ориентир 0. При конечной выборке
значения колеблются. Максимум по тысячам/миллионам ячеек обычно заметно больше
ошибки одной ячейки. Константные индикаторы имеют неопределённую корреляцию.

DDT[a,b] считает входы x, для которых S(x) XOR S(x XOR a) = b. Максимум по a≠0
— дифференциальная равномерность; меньший максимум затрудняет предсказание разностей.
LAT[a,b] = число совпадений parity(a AND x) и parity(b AND S(x)) минус 128.
Это половина коэффициента Уолша. Нелинейность равна
128 − max(|LAT[a,b]|) по всем a и b≠0. Тривиальные маски не включаются в максимум.
Методика: [Carlet, Boolean Functions for Cryptography and Coding Theory,
§§2.3.6, 3.2.3, 3.4.1](https://www.math.univ-paris13.fr/~carlet/book-fcts-Bool-vect-crypt-codes.pdf).

ECB независимо шифрует блоки и сохраняет повторы. В CBC каждый блок зависит от
предыдущего шифротекста; изменение сообщения распространяется вперёд. Изменение
блока шифротекста CBC искажает соответствующий блок сообщения и меняет ровно
тот же бит следующего. CTR складывает сообщение с гаммой через XOR: ошибка
передаётся в один бит. GCM добавляет проверку подлинности, поэтому подмена
должна приводить к отказу. IV/nonce имеет требования, зависящие от режима:
для CBC нужна непредсказуемость, для CTR/GCM — отсутствие повторного использования
гаммы при одном ключе. Эти правила объяснены в SP 800-38A и SP 800-38D,
ссылки и векторы — в `tests/kat/modes/` и `tests/kat/gcm/`.

API анализа находится в `analysis/avalanche/` и `analysis/sbox/`. Тесты проверяют
точные свойства искусственных математических отображений и реальные шифры.
Искусственные отображения проверяют статистический движок и не подменяют KAT.

Ограничения: табличные S-блоки — разрешённое проектом исключение из постоянного
времени; возможна утечка через кеш. Лавинный анализ и DDT/LAT не проверяют такую
утечку. Успешные статистические тесты сами по себе не доказывают безопасность.
