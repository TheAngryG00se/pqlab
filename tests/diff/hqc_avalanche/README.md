# Проверка и измерение HQC v5.1.0

Эксперимент вызывает `hqc_kem_keygen`, `hqc_kem_encaps` и `hqc_kem_decaps` из переносимой
реализации `ref` авторов HQC. Исходники, NIST RNG для проверки и официальные ответы KAT
берутся из одного архива. Коммит, SHA-256 архива, спецификации и трёх файлов ответов
зафиксированы в [описании версии](../../../src/kem/hqc/README.md).

Запуск из корня проекта требует Python 3, CMake ≥ 3.24, Ninja, компиляторы C и C++20,
заголовки и библиотеку OpenSSL для эталонного генератора NIST. При первом скачивании
используется curl. Скрипт сам включает `PQ_WITH_REFERENCE` в отдельной сборке.

```bash
CC=gcc-13 CXX=g++-13 python3 scripts/run_hqc_avalanche.py --samples 768 --output-dir results/hqc-replay
cmp results/hqc-replay/trials.csv results/final/hqc-avalanche/trials.csv
cmp results/hqc-replay/summary.csv results/final/hqc-avalanche/summary.csv
```

Проверенный архив кэшируется в `build/hqc-avalanche/`. Для автономного запуска
можно передать `--archive PATH` с тем же архивом. При каждом запуске скрипт проверяет
SHA-256 и заново извлекает исходники во временный каталог. Результат публикуется
в новом каталоге после успешных проверок всех трёх уровней.

### Как проверяется совпадение с HQC

В версии 5.1.0 KeyGen запрашивает 32 байта `seed_kem` через `randombytes`.
Encaps отдельно запрашивает `m` и 16 байтов соли. Адаптер передаёт эти байты
через штатный интерфейс `randombytes` и проверяет длину и количество обращений.
Криптографические операции внутри эталонной реализации выполняются без правок.

В каждом из 100 официальных случаев на уровень эталонный генератор NIST получает
48-байтовый seed записи и выдаёт входы KeyGen и Encaps. С этими входами адаптер проверяет
побайтовое совпадение `pk`, `sk`, `ct`, `ss` с опубликованным ответом и совпадение
Decaps с Encaps. OpenSSL используется генератором NIST в этой проверке.

### Как строятся пары

Для пары с индексом `i` начальные байты получают с помощью SHAKE256 от точной ASCII-строки
`pqlab/hqc-avalanche/v1/HQC-{уровень}/{i}`, где `i` записан в десятичной форме от нуля
без ведущих нулей. Поток разбивают по порядку на `seed_kem`, `m` и `salt`.
Входной бит с индексом `i mod длина_входа_в_битах` отсчитывается от младшего бита
первого байта. Для 768 пар каждый бит seed изменяется трижды, а каждый бит `m`
изменяется шесть, четыре или три раза на уровнях 1, 3 или 5.

- В KeyGen изменяют один бит `seed_kem` и измеряют расстояние Хэмминга между открытыми ключами.
- В Encaps сохраняют один открытый ключ и одну соль для обеих инкапсуляций пары, изменяют один бит
  `m` и отдельно измеряют расстояния между шифротекстами и между общими секретами.
- Для каждого уровня контроль с исходными входами повторяет первую пару побитово.
  Для каждой пары проверяются расстояние между входами, сохранность соли в обоих шифротекстах
  и успешная декапсуляция обоих шифротекстов исходным секретным ключом.

`trials.csv` содержит номер пары и позиции инверсии, длины и число изменившихся битов.
`summary.csv` содержит среднее, минимум, максимум и выборочное стандартное отклонение
расстояний по парам. Знаменатель для процентов — полная сериализованная длина выхода,
включая соль в шифротексте и биты упаковки. `metadata.json` позволяет сверить источник,
методику и контрольные суммы данных.
