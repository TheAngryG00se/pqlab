# Лавинный анализ

`avalanche.hpp` принимает детерминированную функцию `ByteView → Bytes`, не зная
алгоритма. Нумерация битов: младший бит первого байта — 0. В каждой паре
генерируется новый вход, затем меняется ровно один бит. Ключ, IV и случайные
монеты функции должны оставаться фиксированными; возвращать можно только
публичные наблюдения. Входы хранятся в `SecureBytes`.

Выход: гистограмма расстояния Хэмминга, среднее, генеральная дисперсия,
SAC для каждой пары входного/выходного битов, опционально BIC. BIC — корреляция
между двумя индикаторами изменения выходных битов при фиксированном входном
направлении. При нулевой дисперсии она не определена (`nullopt`), а не равна нулю.
Память ограничена `max_memory_bytes`; полная BIC-матрица значительно больше SAC.

`binomial_chi_square` сравнивает гистограмму с Binomial(n, 1/2), объединяя
соседние интервалы до ожидаемой частоты ≥ 5. Это описательная статистика:
движок не выдаёт p-value и не доказывает независимость или стойкость шифра.

`experiments.hpp` получает алгоритмы только через `Registry`: изменение сообщения
и ключа, одинаковые потоки входов для разных чисел раундов, распространение ошибки
в ECB/CBC/CTR и проверка отказа AEAD. Изменение числа раундов остаётся внутри
`analysis/`. Обычные режимы для эксперимента используют один фиксированный IV;
их результаты не используются для защиты реальных данных.

Проверка: `ctest --preset debug -R 'Avalanche|RealCipherAnalysis'`.
Основа статистики и ограничения описаны в [главе анализа](../../docs/analysis.md).
