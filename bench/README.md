# Замеры скорости и сравнительные графики

Зона участника 4. Движок получает алгоритмы через `pq::Registry`; появившийся в реестре
HQC, шифр или GCM автоматически попадает в соответствующие наборы замеров.
Публичные интерфейсы и реализации криптографических алгоритмов не изменяются.

## Запуск

Из корня репозитория:

```bash
cmake --preset release
cmake --build --preset release
./build/release/apps/pqbench/pqbench --list
./build/release/apps/pqbench/pqbench --suite all --output results/run/bench.csv
python3 scripts/plot_bench.py results/run/bench.csv
```

Последняя команда сохраняет PNG и SVG в `results/run/plots/`.
Для PDF: `--formats png,svg,pdf`; для другого каталога: `--output-dir PATH`.
Нужны Python 3 и matplotlib, предусмотренные планом проекта. Новых C++-зависимостей нет.
Без `--output` CSV сохраняется в `results/<дата>/bench-<время UTC>.csv`.
Явный `--output` перезаписывает указанный файл.

Настройка отдельного сравнения:

```bash
./build/release/apps/pqbench/pqbench --suite kem --iterations 10000 --warmup 100 --output results/kem/bench.csv
./build/release/apps/pqbench/pqbench --suite aead --filter AES --seconds 2 --sizes 16,256,4096,65536,1048576 --output results/aes/bench.csv
./build/release/apps/pqbench/pqbench --suite hybrid --filter ML-KEM-768 --seconds 2 --sizes 4096,65536,1048576 --output results/hybrid/bench.csv
```

Для больших сообщений можно указать размеры вплоть до 64 МиБ и сократить прогрев
через `--warmup 3`. Шифрам нужны размеры, кратные размеру блока; AEAD принимает любые.
До появления настоящих шифров вторые две команды завершаются с сообщением об отсутствии
алгоритмов, не создавая фиктивных результатов.

## Что сравнивается

| Набор | Операции | Единицы графика |
|---|---|---|
| `kem` | `keygen`, `encaps`, `decaps` | мкс на операцию; медиана и p5–p95 в тактах TSC |
| `cipher` | `set_key`, `encrypt`, `decrypt` | МиБ/с для обработки буфера блок за блоком |
| `aead` | `seal`, `open` для каждого шифра × зарегистрированного AEAD-режима | МиБ/с от размера сообщения |
| `hybrid` | `seal`, `open` для каждого KEM × шифра с GCM | мс от размера сообщения |

Время KEM относится к созданию/согласованию секретов. Обработку пользовательских данных
показывают графики шифров, AEAD и гибридного слоя. Сырые блочные операции и AEAD представлены
отдельно: AEAD также выполняет аутентификацию.
Развёртка ключа отдельно измеряется в `set_key`, её строка остаётся в CSV.

Текущий реестр содержит только ML-KEM-512/768/1024. Поэтому сейчас создаются
`kem_latency.png/svg` и `kem_cycles.png/svg`. При появлении остальных реализаций
скрипт создаёт `cipher_encrypt_throughput.*`, `aead_seal_throughput.*`,
`hybrid_seal_latency.*` и соответствующие графики обратных операций.
ECB/CBC/CTR ждут согласованного публичного интерфейса; собственные реализации режимов
в бенчмарке не создаются. Сравнительные замеры с OpenSSL/liboqs пока не подключены.

## Методика

- Используется Release; Debug/RelWithDebInfo отказываются запускать измерения.
- Сначала прогрев, затем минимум 10000 операций для каждого KEM. Для шифров, AEAD и
  гибридного слоя — минимум 1 с суммарного измеренного времени и 30 выборок.
- KEM использует пул из 32 наборов случайных seed/m, подготовленных `SystemRng` вне
  таймера. Измеряются детерминированные API, поэтому в их время не входит `getrandom`.
  Гибридный слой использует обычный API с `SystemRng`, его стоимость входит в результат.
- Для коротких массовых операций одна выборка содержит 64 вызова, для сообщений больше
  4096 байт — один. В CSV записано число вызовов, а время и такты нормированы на вызов.
  p5/p95 и stddev относятся к средним значениям пакетов.
- Таймеры — `steady_clock` и `lfence/rdtsc` на x86. Такты TSC обычно отсчитываются на
  постоянной частоте и не равны тактам ядра при текущей частоте CPU.
  На других архитектурах поля cycles пусты, график тактов не создаётся.
- Результаты защищены от удаления оптимизатором. Публичные API включают свои выделения
  памяти и уничтожение/зануление возвращаемых секретов. Файлового ввода-вывода нет.
- AEAD получает новый nonce на каждое шифрование под тем же ключом. Расшифрование
  измеряется на заранее подготовленном корректном шифротексте.
- Процентили линейно интерполируются; stddev — стандартное отклонение генеральной
  совокупности, не доверительный интервал. Накладные расходы таймеров не вычитаются.
- Скорость = `msg_bytes / median_ns * 10^9 / 2^20`, в МиБ/с. Пустые/несогласованные
  CSV, разные запуски в одном файле, повторы измерений и некорректные числа отвергаются.

Для итогового отчёта измеряйте на одной машине при одинаковых настройках питания и
фоновой нагрузке. Можно привязать процесс к свободному разрешённому логическому CPU:
`taskset -c <номер> ./build/release/apps/pqbench/pqbench ...`.
Температура и динамическая частота влияют на результат; повторите запуск для проверки
устойчивости выводов, сохраняя каждый CSV отдельно.

CSV содержит UTC timestamp, commit (с `-dirty` при рабочих изменениях), CPU, компилятор
и флаги. Commit и флаги фиксируются **при конфигурации CMake**: после коммита или правки
кода повторите `cmake --preset release` и сборку перед итоговым запуском.
Графики сохраняют подпись машины, компилятора, коммита и времени; полные флаги есть в CSV.

## Проверки

```bash
cmake --preset debug
cmake --build --preset debug
ctest --preset debug --output-on-failure
cmake --build --preset debug --target format-check
python3 -m unittest discover -s scripts -p 'test_*.py'
```

Заглушки тестируют прохождение публичных контрактов исключительно в unit-тестах.
Приложение `pqbench` использует только глобальный реестр настоящих алгоритмов.
